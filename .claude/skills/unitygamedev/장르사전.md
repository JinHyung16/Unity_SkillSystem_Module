# 장르사전 — 문법 · 뷰/조작 관례 · 성능 특성 · 장르 함정

장르를 잡으면 해당 절부터 읽는다. 관례는 취향이 아니라 **그 장르가 이미 치른 수업료**다.
관례를 깰 수는 있지만, 깨는 것은 「몰랐다」가 아니라 **「알고 골랐다」**여야 한다.

각 절의 구성: **문법 / 뷰·조작 / 데이터·UI 축 / 성능 특성 / 장르 함정**.
「뷰·조작」 칸이 확정표 2·8행의 기본값이고, 「데이터·UI 축」이 5·6행의 출발점이다.

---

## 서바이버류 (뱀서라이크)

- **문법**: 자동 공격 + 수동 이동. 재미의 축은 「조준」이 아니라 **위치 선정과 빌드 선택**.
  처치 → 드랍 → 성장 → 밀도 상승의 루프가 세션 내내 가속한다
- **뷰·조작**: 2D 유사 탑다운(75~85°) 또는 쿼터뷰. 플레이어 화면 중앙 고정, 카메라 회전 없음.
  모바일 세로는 플로팅 조이스틱 1개가 표준. **Y 정렬 필수** (`View.md` 유사 탑다운 절)
- **데이터·UI 축**: 스킬/증강이 조합형 데이터의 교과서적 사례 — 발사 방식 × 수치 × 속성.
  UI 는 인게임 HUD 1 + 레벨업 선택 팝업 1 + 결과 1이면 루프가 돈다. 밴드 3종으로 시작
- **성능 특성**: **동시 개체 수가 지배 변수.** 풀링·화면 밖 비용 차단·핫패스 무할당이 전제조건.
  적 300 이 목표면 개체별 `Update` 는 처음부터 불가
- **함정**:
  - 스폰을 화면 «안»에서 하면 갑툭튀, 너무 밖에서 하면 밀도가 안 찬다 — **화면 경계 바로 밖**
  - 기울인 카메라의 가시 영역은 사다리꼴 — 원형 스폰 링은 위쪽 편중을 만든다
  - **레벨업 선택 중 월드는 완전 정지**해야 한다 — 시간이 흐르면 선택이 벌칙이 된다
  - 성장 체감은 「수치 +10%」보다 **「발사체 +1 / 신규 스킬」**이 크다 — 선택지 구성에 반영
  - 피격 무적이 없으면 프레임레이트가 곧 난이도가 된다

## 육각/사각 타일 전략 (SLG·타일 점령)

- **문법**: **공간이 자원이다.** 타일의 인접 관계가 전투·확장·경로의 판 자체
- **뷰·조작**: 고정 앵글 쿼터뷰 + 팬/줌 (회전은 대개 없음). 탭 = 선택, 롱탭/더블탭 = 정보.
  화면 → 타일 좌표 변환 유틸이 «단 하나»여야 한다
- **데이터·UI 축**: 화면 수가 폭발하는 장르다 (건물·부대·길드·상점·이벤트…).
  **UI 구조(확정표 6·7)를 슬라이스에서 절대 미루지 않는다** — 화면 20개째에 손을 못 댄다.
  밴드 8종 규모 · 재활용 스크롤 필수 · Window/Panel/Component 3계층이 강제된다
- **구현 분기 — 이게 제일 중요하다**: 타일을 **지형**으로 쓸 것인가 **보드**로 쓸 것인가.
  지형(수천 셀, 경계 블렌딩·높이차)이면 청크 메시 합치기가 맞고,
  보드(수십 노드, 개별 선택·상태 연출)면 개별 GameObject + 좌표계 유틸이 맞다.
  **보드에 지형용 청크 시스템을 들이면 수천 줄을 헛짐으로 진다**
- **성능 특성**: 개체 수보다 **UI 리빌드와 텍스트 갱신**이 병목이 되는 드문 장르
- **함정**: 이동 규칙과 칸 이벤트 규칙의 상호작용(통과 시 발동 × 대량 이동)은 조합 표로 강제 확정

## 퍼즐 (매치·머지·보드)

- **문법**: 규칙은 단순, 상태 공간은 깊게. 재미의 축은 **「읽힘」** — 다음 수가 보이는 판
- **뷰·조작**: 2D 정면 고정. 입력 1종(탭 또는 드래그)으로 전부.
  **입력 실수가 벌칙이 되면 안 된다** (스왑 취소·되돌리기)
- **데이터·UI 축**: 스테이지 = 데이터 1건(보드 초기 상태 + 목표 + 제한).
  UI 는 적지만 연출 타이밍이 많아 **연출 중 입력 잠금 구간**이 UI 스펙의 절반
- **구현**: 보드 상태는 **순수 데이터(2차원 배열)**로 두고 뷰는 그걸 그리기만 —
  로직·뷰가 섞이면 연출 타이밍 바꿀 때마다 규칙이 흔들린다.
  판정이 **헤드리스로 시뮬레이션 가능**해야 데드락 검사·힌트·난이도 자동 검증이 나온다
- **성능 특성**: 대체로 여유롭다. 대신 **연출 큐**가 길어지면 체감 느려짐
- **함정**: 콤보/연쇄 중 새 입력 허용 여부를 초기에 확정. 나중에 바꾸면 전 연출을 다시 짠다

## 액션 (근접·플랫포머·탑다운 슈터)

- **문법**: **입력 → 반응의 지연이 곧 품질**이다. 선입력 버퍼·코요테 타임 같은 관용 처리가 표준
- **뷰·조작**: 플랫포머는 사이드뷰(데드존 + 룩어헤드 필수), 탑다운 슈터는 유사 탑다운 + 조준 축 1개 추가.
  **조작 축이 2개(이동+조준)면 모바일 UI 설계가 통째로 달라진다**
- **데이터·UI 축**: 판정 프레임·경직·무적이 전부 데이터여야 한다. 애니 교체가 판정을 바꾸면 안 된다
- **구현**: 상태머신(또는 BT)으로 캐릭터 상태 전이를 명시. 애니메이션 이벤트와 판정 프레임을 분리
- **성능 특성**: 개체 수는 적지만 **프레임 안정성**이 지배 변수. 튐 하나가 곧 조작 실패다
- **함정**: 히트스톱·넉백·무적 프레임은 「있냐 없냐」가 아니라 **수치 스펙**이다.
  **물리 기반 이동과 커스텀 이동을 섞으면 경계에서 반드시 샌다** — 하나로 통일

## 방치·클리커 (메타 성장 중심)

- **문법**: 세션은 짧고 성장 곡선은 길다. **숫자 인플레이션 관리가 설계의 본체**
- **뷰·조작**: 뷰가 거의 UI다. 월드가 있어도 배경 연출에 가깝다 — **UI 구조가 곧 게임 구조**
- **데이터·UI 축**: 업그레이드 항목 = 데이터 1건 + 곡선. 화면은 목록형이 지배적 →
  **재활용 스크롤 + 값 갱신 최소화**가 UI 규약의 전부에 가깝다
- **구현**: 큰 수 처리(지수 표기) · 오프라인 경과 정산 · **저장 데이터 마이그레이션**을 초기에.
  밸런스 수식은 전부 데이터로 — 이 장르는 상수 튜닝이 개발의 절반이다
- **성능 특성**: 텍스트 갱신이 유일한 병목. 초당 1회 틱으로 충분한 것을 매 프레임에 두지 않는다
- **함정**: 오프라인 정산은 「이득 재현」이 아니라 **수식 근사**로 —
  실시간 시뮬레이션 재생은 안 터지는 게 이상한 것. 기기 시계 조작을 전제로 설계한다

## 카드·덱빌딩

- **문법**: 카드 1장 = **데이터 1건 + 효과 원자의 조합.** 효과 원자를 늘리는 것과 카드를 늘리는 것을 구분
- **뷰·조작**: 2D 정면. 드래그 & 드롭이 주 입력 → **드래그 임계치·취소 규칙**이 스펙
- **데이터·UI 축**: 조합형 데이터의 또 다른 교과서. **카드 텍스트를 데이터에서 생성**(수치 포함) —
  텍스트와 실효과가 어긋나는 게 이 장르 최다 버그
- **구현**: 효과는 **큐 기반 해석**(스택/순차)으로 — 즉시 실행으로 섞으면 연쇄 효과 순서 버그가 난다
- **성능 특성**: 여유롭다. 대신 카드 아트가 메모리를 먹는다 — 보이는 것만 로드
- **함정**: 무작위(드로우)는 **시드 고정 리플레이**가 가능해야 밸런스 실측이 된다

## 새 장르를 잡았는데 절이 없다

1. 레퍼런스 2~3개를 실측한다 (`레퍼런스분석.md` — 영상 프레임 추출 → 화면/루프 분석)
2. 위 구성(문법 / 뷰·조작 / 데이터·UI 축 / 성능 / 함정)으로 **절을 먼저 쓴다** —
   쓰면서 모르는 것이 그대로 착수 질문이 된다
3. 개발 중 이 장르 고유의 사고가 나면 그 절에 `[사고]` 로 남긴다
4. 한 바퀴 끝났으면 **그 장르 절에 「실측으로 확인된 것」을 한 줄씩 보탠다**

**절을 안 쓰고 착수하면, 그 장르의 수업료를 우리가 처음부터 다시 낸다.**
